# 可选路径算法与统一输出设计总结

> 本文总结本次开发分支的主要内容，重点说明 BFS/A* 参数选择、路径显示和输出结构。

## 1. 本次改动目标

本次开发在已有迷宫生成、随机出口、seed 复现和几何 A* 的基础上，完成以下改进：

1. 保留原有 BFS 格子路径搜索；
2. 增加 `-bfs` 和 `-astar` 参数，允许用户选择路径算法；
3. 将完美迷宫参数统一为 `-perfect`；
4. 支持参数按照任意顺序组合；
5. 每次只展示用户选择的路径算法结果；
6. A* 结果使用 `*` 标记小鼠经过的格子；
7. 保持 ASCII 输出简单直观。

## 2. 命令行参数

程序基本格式为：

```bash
./gradlew run --args='m n [选项]'
```

示例：

```bash
./gradlew run --args='7 9 -perfect seed-course -bfs'
./gradlew run --args='7 9 -perfect seed-course -astar'
```

支持的选项如下：

| 参数 | 含义 |
|---|---|
| `-perfect` | 生成完美迷宫 |
| `seed-<string>` | 使用固定字符串种子生成可复现迷宫 |
| `-bfs` | 使用 BFS 按格子搜索 |
| `-astar` | 使用 A* 按几何距离搜索 |

如果不指定 `-bfs` 或 `-astar`，程序默认使用 BFS，以兼容之前的运行方式。

`-bfs` 和 `-astar` 不能同时使用，否则程序会提示参数错误。

## 3. BFS 路径搜索

BFS 实现保留在：

```text
src/main/java/org/example/solver/MazeSolver.java
```

BFS 使用队列，从入口开始逐层访问迷宫中的格子。只有满足以下条件的格子才会加入队列：

- 坐标合法；
- 当前方向没有墙；
- 格子尚未访问。

BFS 使用前驱节点记录搜索过程，找到出口后回溯得到完整路径。

由于每次移动一个格子的代价相同，BFS 可以保证找到经过格子数最少的路径。

使用命令：

```bash
./gradlew run --args='7 9 -bfs'
```

输出示例：

```text
--- BFS 最短路径 ---
路径长度: 31 个格子
访问状态数: 56
搜索耗时: 0.377 ms
迷宫生成耗时: 1.298 ms
```

## 4. A* 几何路径搜索

A* 实现位于：

```text
src/main/java/org/example/solver/AStarMazeSolver.java
```

A* 不再单纯把格子当作节点，而是建立几何路径图：

- 格子中心作为几何节点；
- 可通行墙的中点作为几何节点；
- 节点之间的直线或斜线距离作为边权；
- 搜索状态包含当前位置和运动方向。

A* 的代价函数为：

```text
f(n) = g(n) + h(n)
```

其中：

- `g(n)` 是起点到当前节点的实际几何距离；
- `h(n)` 是当前节点到终点的欧氏距离估计值。

由于小鼠速度设为 `1 unit/s`，因此：

```text
预计移动时间 = 几何路径长度
```

使用命令：

```bash
./gradlew run --args='7 9 -astar'
```

输出示例：

```text
--- A* 最短路径 ---
几何路径长度: 5.828 units
访问状态数: 23
搜索耗时: 29.689 ms
迷宫生成耗时: 1.360 ms
```

## 5. A* 路径的 ASCII 显示方式

ASCII 字符集中没有合适的 45° 斜线符号，因此程序不尝试绘制 A* 的真实几何折线。

当前显示策略是：

1. A* 仍然按照几何距离搜索；
2. 读取 A* 路径经过的几何节点；
3. 将格子中心和墙中点转换为对应的格子；
4. 在这些格子中使用 `*` 标记。

因此，地图中的 `*` 表示：

```text
小鼠经过的格子
```

而不是：

```text
小鼠实际运动的直线或斜线
```

这样可以在同一个 ASCII 地图中直观比较 BFS 和 A* 经过的格子差异，同时保留 A* 的实际几何距离统计。

## 6. 统一输出设计

程序会根据所选算法只输出对应的路径统计，不再同时展示 BFS、DFS 和 A* 的对比数据。

迷宫基本信息保持普通文本形式：

```text
--- 迷宫统计 ---
尺寸: 7 x 9
总格子数: 63
入口: (0, 0)
出口: (3, 0)
```

BFS 输出：

```text
--- BFS 最短路径 ---
路径长度: ...
访问状态数: ...
搜索耗时: ...
迷宫生成耗时: ...
```

A* 输出：

```text
--- A* 最短路径 ---
几何路径长度: ...
访问状态数: ...
搜索耗时: ...
迷宫生成耗时: ...
```

这样可以避免用户在一次测试中看到与当前目标无关的算法统计。

## 7. 相关类结构

本次新增或调整的主要类如下：

| 类 | 职责 |
|---|---|
| `SearchAlgorithm` | 定义 `BFS` 和 `A*` 两种搜索模式 |
| `MazeSolver` | 保留 BFS 和 DFS 搜索实现 |
| `AStarMazeSolver` | 执行几何 A* 搜索 |
| `MazeGeometryGraph` | 构造格子中心、墙中点和几何边 |
| `GeometricPathResult` | 保存 A* 路径、距离和访问状态数 |
| `GameStatistics` | 根据所选算法输出对应统计信息 |
| `Main` | 解析参数、选择算法、渲染路径和输出统计 |

## 8. 测试情况

运行自动化测试：

```bash
./gradlew test
```

已验证：

1. BFS 参数可以正常运行；
2. A* 参数可以正常运行；
3. 不指定算法时默认使用 BFS；
4. `-bfs` 与 `-astar` 同时使用时能够报错；
5. `-perfect` 参数可以正常使用；
6. 固定 seed 可以生成相同迷宫；
7. A* 可以输出几何路径和经过格子的 `*` 标记；
8. BFS 和 A* 的输出不再混合；
9. A* 相邻格子距离和 L 形 45° 转弯测试通过。

## 9. 使用示例

### BFS 模式

```bash
./gradlew run --args='7 9 -perfect seed-course -bfs'
```

适合比较：

- 经过的格子数；
- BFS 的最短格子路径；
- BFS 搜索访问量。

### A* 模式

```bash
./gradlew run --args='7 9 -perfect seed-course -astar'
```

适合比较：

- 几何路径长度；
- 预计移动时间；
- A* 搜索访问状态数；
- A* 经过的格子集合。

### 对比同一个迷宫

为了保证两次测试使用完全相同的迷宫，应固定相同的行数、列数、生成模式和 seed，只切换算法参数：

```bash
./gradlew run --args='7 9 -perfect seed-course -bfs'
./gradlew run --args='7 9 -perfect seed-course -astar'
```

两次运行中的迷宫墙壁、出口位置和随机过程保持一致，但搜索算法和输出路径不同。

## 10. 总结

本次开发将 BFS 和 A* 统一到命令行可选模式中：

- BFS 解决按格子移动的最短路径问题；
- A* 解决带几何距离和转弯规则的路径问题；
- `-bfs` 和 `-astar` 控制当前测试使用的算法；
- A* 虽然不绘制真实斜线，但通过 `*` 标记经过格子；
- 统计输出只展示当前选择的算法，结构更加清晰。

该设计既保留了原有 BFS 功能，又为后续引入更精确的鼠标运动模型和图形化路径显示留下了扩展空间。
