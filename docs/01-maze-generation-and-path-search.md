# 迷宫生成与路径搜索系统设计总结

> 本文对应已创建的 PR #1，内容范围截至提交 `9674528`。
> 当前后续开发分支中的随机出口位置改动不包含在本次总结中。

## 1. 项目目标

本项目实现一个基于 Java 的迷宫生成与路径搜索系统，主要完成两项任务：

1. 自动生成一个连通、无环的随机迷宫；
2. 从入口开始搜索到出口的路径，并在控制台中可视化输出。

项目按照面向对象思想拆分迷宫数据、生成算法、搜索算法、渲染和统计等职责，使各部分可以独立理解、测试和扩展。

## 2. 算法选择及理由

### 2.1 迷宫生成：随机 DFS + 回溯

迷宫生成使用随机深度优先搜索（Depth-First Search，DFS）和回溯算法。

选择理由：

- 逻辑清晰，适合数据结构课程实验；
- 使用栈即可实现，容易体现 DFS 和回溯思想；
- 每次只连接当前格子与一个未访问邻居；
- 最终能够生成连通且无环的“完美迷宫”；
- 通过随机选择邻居，可以生成不同的迷宫布局。

具体过程：

1. 随机选择一个格子作为起点；
2. 将当前格子标记为已访问；
3. 获取当前格子的未访问邻居；
4. 随机选择一个邻居，移除两个格子之间的墙；
5. 将当前格子压入栈，并移动到新格子；
6. 如果当前格子没有未访问邻居，则从栈中弹出格子并回溯；
7. 重复上述过程，直到全部格子被访问；
8. 重置格子的 `visited` 状态，为后续路径搜索准备。

生成算法使用 `Deque<Cell>` 模拟栈。每个格子被访问一次，每次最多检查四个方向。

### 2.2 路径搜索：BFS

路径搜索使用广度优先搜索（Breadth-First Search，BFS）。

选择理由：

- BFS 适合在网格中搜索路径；
- 使用队列实现，结构简单；
- 可以按距离从近到远逐层搜索；
- 当每次移动代价相同时，可以保证找到入口到出口的最短路径；
- 使用前驱节点可以还原完整路径，而不仅仅是判断是否可达。

具体过程：

1. 将入口加入队列并标记为已访问；
2. 从队列中取出当前格子；
3. 依次检查上下左右四个方向；
4. 只有在相邻格子合法、当前方向没有墙、相邻格子未访问时才继续；
5. 记录相邻格子的前驱节点，并将其加入队列；
6. 搜索到出口后停止；
7. 从出口沿 `parent` 映射回溯到入口；
8. 反转回溯结果，得到入口到出口的完整路径。

## 3. 实现逻辑

### 3.1 墙壁模型

每个 `Cell` 保存四面墙的状态：

```text
topWall
rightWall
bottomWall
leftWall
```

迷宫初始化时，每个格子的四面墙都存在。相邻格子之间的墙需要保持同步。

例如，移除左侧格子的右墙时，同时移除右侧格子的左墙。该逻辑集中放在 `Maze.removeWall` 中，避免生成器直接修改两个格子的内部状态而造成不一致。

### 3.2 迷宫生成流程

`Main` 创建 `Maze` 后调用 `MazeGenerator.generate`。生成器负责修改格子的墙壁并维护生成阶段的访问状态，生成完成后调用 `resetVisited`。

入口在当前 PR 版本中固定为左上角 `(0, 0)`，出口固定为右下角 `(rows - 1, cols - 1)`。

### 3.3 路径搜索流程

`Main` 设置入口和出口后调用 `MazeSolver.findPath`。求解器只读取迷宫墙壁结构，不修改迷宫的墙壁。

搜索结果使用 `List<Cell>` 表示，列表顺序为：

```text
入口 -> 中间格子 -> 出口
```

如果没有路径，则返回空列表。

### 3.4 控制台显示流程

`MazeRenderer` 使用 ASCII 字符绘制迷宫：

- `+---` 表示水平墙；
- `|` 表示垂直墙；
- `S` 表示入口；
- `E` 表示出口；
- `*` 表示 BFS 找到的路径；
- 空格表示普通区域。

渲染器只负责读取迷宫数据和路径，不参与生成或搜索。

### 3.5 统计流程

`GameStatistics` 保存并输出：

- 迷宫行数和列数；
- 总格子数量；
- 入口和出口坐标；
- 路径长度；
- BFS 访问格子数量；
- 迷宫生成耗时；
- 路径搜索耗时。

```text

```

各模块职责如下：

| 类 | 主要职责 |
|---|---|
| `Direction` | 定义四个移动方向、坐标变化量和相反方向 |
| `Cell` | 保存格子坐标、访问状态和四面墙状态 |
| `Maze` | 管理二维格子、坐标合法性、邻居和同步拆墙 |
| `MazeGenerator` | 使用随机 DFS 回溯生成迷宫 |
| `MazeSolver` | 使用 BFS 搜索最短路径 |
| `MazeRenderer` | 将迷宫和路径绘制到控制台 |
| `GameStatistics` | 保存并格式化实验统计数据 |
| `Main` | 组织程序执行流程 |

## 5. 复杂度分析

设迷宫格子数量为：

```text
V = rows × cols
```

### BFS 搜索

每个格子最多检查四个方向，因此理论复杂度为：

```text
时间复杂度：O(V)
空间复杂度：O(V)
```

### ASCII 渲染

每个格子绘制一次：

```text
时间复杂度：O(V)
空间复杂度：O(V)
```

### DFS 迷宫生成

随机 DFS 回溯本身的理想复杂度为：

```text
时间复杂度：O(V)
空间复杂度：O(V)
```

但是当前实现使用 `hasUnvisitedCell` 反复扫描整个二维数组判断是否存在未访问格子，因此严格分析时，生成过程最坏接近：

```text
时间复杂度：O(V²)
空间复杂度：O(V)
```

对于课程实验中的小型迷宫影响不明显，但大尺寸迷宫时应进行优化。

## 6. 当前版本的测试

当前测试覆盖：

1. `5 x 5` 迷宫的全连通性；
2. `10 x 20` 矩形迷宫的 BFS 搜索；
3. BFS 路径的起点和终点是否正确；
4. 路径相邻格子之间是否存在合法通道；
5. 拆除一面墙时，两个相邻格子的墙状态是否同步。

运行命令：

```bash
./gradlew test
./gradlew run --args='5 5'
./gradlew run --args='10 20'
```

## 7. 可优化的地方

### 7.1 优先优化迷宫生成复杂度

当前生成器每轮通过扫描整个迷宫查找未访问格子。可以维护一个 `visitedCount`，当访问数量达到 `rows * cols` 时直接结束循环，避免重复扫描。

优化后，生成算法可以稳定接近：

```text
时间复杂度：O(V)
```

### 7.2 删除重复的随机操作

当前邻居选择逻辑同时使用了 `Collections.shuffle` 和随机下标选择。两者功能重复，可以保留其中一种，以减少不必要的操作并使代码更清晰。

### 7.3 支持随机种子

当前使用无参 `Random`，每次运行都会产生不同结果。可以允许传入固定随机种子，使同一个种子生成相同迷宫，方便：

- 调试；
- 编写稳定测试；
- 对比不同算法；
- 截取实验报告中的固定结果。

### 7.4 增加完美迷宫验证

可以统计拆除的内部墙数量。对于 `V` 个格子的完美迷宫，理论上应拆除：

```text
V - 1
```

再结合全图连通性测试，可以验证迷宫无环且连通。

### 7.5 增加 DFS 路径搜索对比

可以增加基于栈的 DFS 求解器，与 BFS 比较：

- 访问节点数量；
- 搜索耗时；
- 返回路径长度。

BFS 可以保证最短路径，而 DFS 只保证在存在路径时找到一条路径。

### 7.6 完善入口和出口表现

当前入口和出口主要通过 `S`、`E` 字符标记，迷宫外边界仍然完整。后续可以移除入口和出口处的边界墙，使显示效果更接近真实迷宫。

### 7.7 增强参数校验和用户交互

当前程序通过命令行参数设置行数和列数。后续可以增加：

- 更友好的非法参数提示；
- 交互式输入；
- 最大迷宫尺寸限制；
- 输出到文件；
- 图形化界面。

## 8. 总结

当前版本使用面向对象结构完成了迷宫生成、BFS 最短路径搜索、控制台可视化和统计输出。核心算法均使用 Java 标准库实现，代码结构适合课程实验和后续扩展。

当前实现已经满足最小可运行要求。后续开发应优先改进生成器的复杂度和测试完整性，再增加随机出口、DFS 对比或图形界面等功能。
