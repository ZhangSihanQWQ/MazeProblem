# 可配置完美迷宫与生成验证优化总结

## 1. 本次改动目标

本次开发在基础迷宫生成和 BFS 路径搜索的基础上，完成以下改进：

1. 入口继续固定在左上角；
2. 出口不再固定在右下角，可以随机位于迷宫内部或边缘；
3. 优化随机 DFS 生成算法的时间复杂度；
4. 删除邻居选择中的重复随机操作；
5. 允许用户通过 `--perfect` 参数选择是否生成完美迷宫；
6. 增加完美迷宫验证器；
7. 增加对应的单元测试和边界测试。

## 2. 出口位置优化

入口仍然设置为：

```text
(0, 0)
```

出口从迷宫所有格子中随机选择，但不会与入口重合。例如运行 `7 x 9` 迷宫时，出口可能是：

```text
(2, 5)
(4, 5)
(6, 4)
```

由于迷宫生成后所有格子都是连通的，因此出口无论位于角落、边缘还是中间位置，BFS 都可以搜索到它。

对于 `1 x 1` 迷宫，入口和出口只能是同一个格子，程序会特殊处理，避免随机选择时出现死循环。

## 3. `perfect` 参数设计

当前命令行参数约定如下：

```bash
./gradlew run --args='7 9 --perfect'
```

显式使用 `--perfect` 时，生成完美迷宫。

```bash
./gradlew run --args='7 9'
```

不提供第三个参数时，生成普通连通迷宫。

如果第三个参数不是 `--perfect`，程序会提示参数格式错误。

默认不启用完美迷宫模式的原因是将选择权交给用户，同时保留命令行使用的简洁性。对于课程实验，可以分别运行两种模式并比较它们的结构差异。

## 4. 迷宫生成算法优化

### 4.1 使用访问计数结束生成

基础版本通过扫描整个二维数组判断是否还有未访问格子。该操作会被重复执行，使生成算法最坏情况下接近 `O(V²)`，其中：

```text
V = rows × cols
```

本次改为维护：

```java
int visitedCount
```

每访问一个新格子就将计数加一，当访问数量达到总格子数时结束生成：

```text
visitedCount == rows × cols
```

优化后的生成流程：

1. 随机选择起始格子；
2. 标记起始格子并将 `visitedCount` 设为 `1`；
3. 只要 `visitedCount` 小于总格子数，就继续 DFS；
4. 有未访问邻居时拆墙并前进；
5. 没有未访问邻居时从栈中回溯；
6. 生成完成后重置所有格子的访问状态。

优化后，标准 DFS 回溯生成过程的时间复杂度为：

```text
O(V)
```

空间复杂度仍为：

```text
O(V)
```

### 4.2 删除重复随机操作

原来的邻居选择同时使用了列表打乱和随机下标：

```java
Collections.shuffle(result, random);
result.get(random.nextInt(result.size()));
```

两次随机操作是重复的。本次保留随机下标选择：

```java
result.get(random.nextInt(result.size()));
```

这样既保持随机性，也减少了不必要的计算。

## 5. 两种迷宫生成模式

### 5.1 完美迷宫模式

执行：

```java
generator.generate(maze, true);
```

程序只使用随机 DFS 回溯生成一棵连通树。每次拆墙都会把一个未访问格子接入已有结构，因此最终不会产生环。

### 5.2 普通连通迷宫模式

执行：

```java
generator.generate(maze, false);
```

程序先生成一个完美迷宫，保证所有格子连通；然后从仍然存在的内部墙中随机选择若干面拆除，增加额外通道。

增加额外通道后：

- 迷宫仍然连通；
- 迷宫中可能存在环；
- 某些格子之间可能出现多条路线；
- 入口到出口的路径不一定唯一。

这种方式可以在保证可达性的基础上生成结构更加开放的普通迷宫。

## 6. 完美迷宫验证

新增类：

```text
src/main/java/org/example/validator/MazeValidator.java
```

### 6.1 完美迷宫的定义

将迷宫抽象成图：

- 每个格子是一个节点；
- 两个格子之间没有墙，表示它们之间有一条边；
- 墙壁表示两个格子之间不能直接移动。

完美迷宫需要同时满足：

1. 所有格子互相连通；
2. 任意两个格子之间只有一条路径；
3. 迷宫中没有环。

在图论中，这相当于一个树结构。对于 `V` 个格子，完美迷宫的通道数量必须是：

```text
V - 1
```

例如 `5 x 5` 迷宫有 25 个格子，因此完美迷宫应有：

```text
25 - 1 = 24
```

条通道。

### 6.2 验证逻辑

`MazeValidator` 主要执行两项检查：

1. 从 `(0, 0)` 开始 BFS，统计可以访问到的格子数量；
2. 统计所有没有墙的相邻格子连接数量。

判断条件为：

```text
可访问格子数 == 总格子数
并且
通道数量 == 总格子数 - 1
```

统计通道时只检查每个格子的右侧和下侧，避免同一条通道被重复统计。

主程序会输出：

```text
生成模式: 完美迷宫
完美迷宫验证: 通过
```

或者：

```text
生成模式: 普通连通迷宫
完美迷宫验证: 未通过
```

普通连通迷宫验证不通过是预期结果，因为它包含额外通道和环，但不代表它不可达。

## 7. 项目结构变化

本次新增验证器：

```text
src/main/java/org/example/
├── generator/
│   └── MazeGenerator.java
├── validator/
│   └── MazeValidator.java
└── ...
```

主要职责：

| 类 | 本次职责 |
|---|---|
| `Main` | 解析 `--perfect` 参数，选择生成模式并输出验证结果 |
| `MazeGenerator` | 使用访问计数优化 DFS 生成，并支持两种模式 |
| `MazeValidator` | 检查迷宫连通性、通道数量和完美迷宫条件 |
| `MazeTest` | 测试完美生成、普通连通生成、路径和边界情况 |

## 8. 测试与验证

本次执行了以下测试：

### 单元测试

```bash
./gradlew test
```

测试通过，覆盖：

- 完美迷宫通道数量；
- 完美迷宫连通性；
- 普通迷宫仍然连通；
- 普通迷宫包含额外通道；
- BFS 路径合法性；
- 中间位置出口；
- `1 x 1` 迷宫；
- 相邻格子拆墙同步。

完美模式：

```bash
./gradlew run --args='7 9 --perfect'
```

普通模式：

```bash
./gradlew run --args='7 9'
```

两种模式都能在控制台显示迷宫、入口 `S`、出口 `E` 和 BFS 路径 `*`。

## 9. 本次改动的收益

本次 PR 使系统具备了更强的可配置性和可验证性：

- 用户可以选择迷宫是否为完美迷宫；
- 生成算法不再重复扫描全部格子；
- 可以从结构上验证完美迷宫，而不是只观察输出；
- 出口位置更加灵活；
- 普通迷宫仍然保持全局连通；
- 测试覆盖了算法逻辑和边界情况。

## 10. 后续可优化方向

1. 支持传入随机种子，使测试和实验结果可复现；
2. 将随机出口选择抽取为独立的端点选择器；
3. 增加 DFS 路径搜索，与 BFS 比较访问数量和路径长度；
4. 让验证器返回具体失败原因，而不仅返回布尔值；
5. 限制最大迷宫尺寸，避免用户输入过大导致资源消耗；
6. 增加入口和出口的边界开口；
7. 将 ASCII 输出保存到文件或增加图形化显示。
